THE BOSS
Development notes · Recovery · Privacy policy

Personal software development project

Documents, review and a recoverable ledger.

THE BOSS is a personal, non-commercial software project for organising financial source documents, reviewing extracted information and maintaining a traceable workspace ledger. Development focuses on preserving the relationship between a document, its reviewed records and the evidence needed to recover a workspace. Google Drive is an optional storage component of its recovery workflow.

Development status: a private codebase under active development. This public site describes the software and its recovery engineering. It offers no public application, financial service, account sign-in or access to private workspaces.

What the software brings together

  • Workspace records: a local SQLite ledger associated with a specific workspace identity.
  • Source documents: encrypted originals retained for authentication and later review.
  • Review evidence: checkpoint ledgers and consistency checks used to assess whether records survive an export and restore.
  • Portable recovery: supported export packages and isolated restore tools that validate compatibility before accepting a workspace.

A simplified workflow is: source document → extracted information → owner review → ledger and checkpoint evidence → portable recovery package. Private records and original documents are not published on this site.

The software engineering work

The recovery components use Python on Windows and SQLite. Development work includes checking physical database schemas and fingerprints, maintaining compatible export and restore components, packaging dependencies for offline installation, and recording reproducible integrity checks.

Recovery validation checks database integrity, workspace identity, supported financial-row preservation, checkpoint ledgers and authentication of encrypted original documents. Synthetic tests use fictional records and disposable credentials so that recovery behaviour can be tested without publishing private data.

Read the development notes for the component design, a real schema-compatibility problem, the synthetic test method, recorded milestones and remaining work. The application source remains private; this website publishes documentation rather than application code or private test receipts.

Recovery is part of the project

The backup layer uses existing open-source tools: restic creates authenticated encrypted snapshots, and rclone transfers encrypted repository files to owner-controlled storage. Those tools are not presented as software developed by this project.

An encrypted off-site copy has passed an independent download and complete repository integrity check with the local backup drive disconnected. Snapshot mappings, file checksums and recovery-kit receipts were verified. This demonstrates that the captured repository can be read independently of that drive; it does not demonstrate complete recovery of every source or a working application on replacement hardware.

Remaining engineering work includes complete source coverage and a clean-machine recovery rehearsal. Current verification has not established full replacement-PC or desktop-application recovery. No recurring backup schedule or automatic pruning is enabled.

Google Drive connection and privacy

The owner's desktop backup connection requests only https://www.googleapis.com/auth/drive.file. This permits creating, reading, updating and deleting files created by or explicitly made available to the app. It does not grant general access to every existing Drive file, Gmail or Google Photos.

Restic encrypts backup contents locally before authorised transfers. Recovery passwords are held separately. This website does not collect Google credentials, accept uploads or expose backup contents. Read the privacy policy for the connection's data practices and account controls.
